## 2. Теоретичні відомості

### 2.1. Що таке система неперетинних множин

Система неперетинних множин, або **Union-Find**, зберігає об’єкти, поділені на окремі групи. Один об’єкт може належати лише одній групі.

Наприклад, спочатку п’ять комп’ютерів не з’єднані між собою:

```text
{0} {1} {2} {3} {4}
```

Структура підтримує дві основні операції:

- `Union(p, q)` — об’єднує групи, у яких перебувають елементи `p` і `q`;
- `Connected(p, q)` — перевіряє, чи належать `p` і `q` одній групі.

Операція `Connected` повертає `true`, якщо елементи належать одній групі, і `false`, якщо вони належать різним групам.

### 2.2. Quick Find

У Quick Find використовується масив `id`. Індекс масиву — номер елемента, а значення `id[i]` — номер групи, до якої він належить.

```text
Індекс:     0  1  2  3  4
id:        [0, 1, 2, 3, 4]
```

Спочатку всі значення різні, тому кожен елемент утворює окрему групу. Щоб перевірити зв’язок між `p` і `q`, достатньо порівняти `id[p]` та `id[q]`. Під час `Union(p, q)` програма проходить увесь масив і замінює номер групи елемента `p` на номер групи елемента `q`.

### 2.3. Quick Union

У Quick Union масив `parent` зберігає «батька» кожного елемента. Так утворюються дерева. Якщо елемент є коренем дерева, він посилається сам на себе.

```text
parent[2] = 2  → елемент 2 є коренем
parent[1] = 2  → елемент 1 веде до кореня 2
```

Щоб перевірити зв’язок, програма переходить від кожного елемента до його кореня. Якщо корені однакові, елементи зв’язані.

### 2.4. Позначення складності

- `O(...)` показує верхню оцінку: як багато операцій може знадобитися алгоритму;
- `Ω(...)` показує нижню оцінку: як мало операцій може бути достатньо;
- `Θ(...)` означає, що кількість операцій зростає з указаною швидкістю і зверху, і знизу.

| Складність | Приблизна кількість операцій для `n = 10` | Просте пояснення |
|---|---:|---|
| `O(1)` | 1 | Кількість дій майже не залежить від розміру даних |
| `O(log n)` | 3–4 | На кожному кроці обсяг роботи суттєво зменшується |
| `O(n)` | 10 | Потрібно переглянути всі елементи |
| `O(n²)` | 100 | Для кожного елемента повторно переглядаються інші елементи |

Якщо Quick Find виконує `Union` для масиву з 5 елементів, цикл перевіряє 5 позицій. Для 10 елементів — 10 позицій, для 100 елементів — 100 позицій. Кількість перевірок зростає пропорційно до `n`.

### 2.5. Обов’язковий наочний приклад

Нехай є п’ять комп’ютерів. Розглянемо Quick Find.

**Початковий стан:**

```text
Групи: {0} {1} {2} {3} {4}
id:    [0, 1, 2, 3, 4]
```

**Операція 1: `Union(1, 2)`**

Група комп’ютера `1` має номер `1`, а група комп’ютера `2` — номер `2`. Програма замінює всі значення `1` на `2`.

```text
Групи: {0} {1, 2} {3} {4}
id:    [0, 2, 2, 3, 4]
```

**Операція 2: `Union(2, 4)`**

Комп’ютер `2` належить групі `2`, а комп’ютер `4` — групі `4`. Програма замінює всі значення `2` на `4`.

```text
Групи: {0} {1, 2, 4} {3}
id:    [0, 4, 4, 3, 4]
```

**Перевірка `Connected(1, 4)`**

```text
id[1] = 4
id[4] = 4
Результат: true
```

Обидва значення однакові, тому комп’ютери належать одній групі.

**Перевірка `Connected(0, 4)`**

```text
id[0] = 0
id[4] = 4
Результат: false
```

Значення різні, тому комп’ютери належать різним групам.

## 6. Кодовий приклад

Приклад використовує п’ять елементів, виконує дві операції об’єднання та показує внутрішні масиви Quick Find і Quick Union. Методи розташовані в одному класі, щоб увесь алгоритм був перед очима.

### Файл `Source/Practical1.cs`

```csharp
namespace TheoryOfAlgorithms.Source;

public static class Practical1
{
    // Запускає приклад із конкретними вхідними даними.
    public static void Run()
    {
        int count = 5; // Елементи мають номери від 0 до 4.
        int[] quickFind = CreateInitialArray(count); // Номери груп.
        int[] quickUnion = CreateInitialArray(count); // Батьки елементів.

        Console.WriteLine("Початкові масиви:");
        PrintArray("Quick Find", quickFind);
        PrintArray("Quick Union", quickUnion);

        // Однакове об'єднання виконуємо двома алгоритмами.
        UnionQuickFind(quickFind, 1, 2);
        UnionQuickUnion(quickUnion, 1, 2);
        Console.WriteLine("Після Union(1, 2):");
        PrintArray("Quick Find", quickFind);
        PrintArray("Quick Union", quickUnion);

        UnionQuickFind(quickFind, 2, 4);
        UnionQuickUnion(quickUnion, 2, 4);
        Console.WriteLine("Після Union(2, 4):");
        PrintArray("Quick Find", quickFind);
        PrintArray("Quick Union", quickUnion);

        Console.WriteLine($"Quick Find Connected(1, 4): {ConnectedQuickFind(quickFind, 1, 4)}");
        Console.WriteLine($"Quick Union Connected(1, 4): {ConnectedQuickUnion(quickUnion, 1, 4)}");
        Console.WriteLine($"Quick Find Connected(0, 4): {ConnectedQuickFind(quickFind, 0, 4)}");
        Console.WriteLine($"Quick Union Connected(0, 4): {ConnectedQuickUnion(quickUnion, 0, 4)}");
    }

    // Створює початковий масив [0, 1, 2, ..., count - 1].
    public static int[] CreateInitialArray(int count)
    {
        int[] values = new int[count];
        for (int i = 0; i < count; i++)
            values[i] = i;
        return values;
    }

    // Замінює номер першої групи номером другої групи.
    public static void UnionQuickFind(int[] id, int first, int second)
    {
        int firstGroup = id[first];
        int secondGroup = id[second];
        for (int i = 0; i < id.Length; i++)
            if (id[i] == firstGroup)
                id[i] = secondGroup;
    }

    // Перевіряє, чи однакові номери груп двох елементів.
    public static bool ConnectedQuickFind(int[] id, int first, int second)
    {
        return id[first] == id[second];
    }

    // Переходить від елемента до кореня його дерева.
    public static int FindRoot(int[] parent, int element)
    {
        while (parent[element] != element)
            element = parent[element];
        return element;
    }

    // Приєднує корінь першого дерева до кореня другого.
    public static void UnionQuickUnion(int[] parent, int first, int second)
    {
        int firstRoot = FindRoot(parent, first);
        int secondRoot = FindRoot(parent, second);
        parent[firstRoot] = secondRoot;
    }

    // Порівнює корені двох елементів у Quick Union.
    public static bool ConnectedQuickUnion(int[] parent, int first, int second)
    {
        return FindRoot(parent, first) == FindRoot(parent, second);
    }

    // Виводить назву та всі елементи масиву.
    public static void PrintArray(string name, int[] values)
    {
        Console.WriteLine($"{name}: [{string.Join(", ", values)}]");
    }
}
```

## 7. Перевірка коректності

**Тестовий випадок** — це конкретні вхідні дані та відомий очікуваний результат. Якщо фактичний результат збігається з очікуваним, перевірка успішна.

| № | Вхідні дані | Що перевіряється | Очікуваний результат |
|---:|---|---|---|
| 1 | `count=5`, `Union(1,2)`, `Union(2,4)` | Звичайне об’єднання | `Connected(1,4)=true` |

| 4 | `count=4`, `Union(0,1)` | Різні групи | `Connected(0,3)=false` |

### Файл `Tests/Practical1Tests.cs`

```csharp
using TheoryOfAlgorithms.Source;

namespace TheoryOfAlgorithms.Tests;

public static class Practical1Tests
{
    public static void RunTests()
    {
        // Після двох об'єднань елементи 1 і 4 мають бути зв'язані.
        int[] firstTest = Practical1.CreateInitialArray(5);
        Practical1.UnionQuickFind(firstTest, 1, 2);
        Practical1.UnionQuickFind(firstTest, 2, 4);
        Check("Елементи 1 і 4 зв'язані",
            Practical1.ConnectedQuickFind(firstTest, 1, 4), true);

        // Елементи 0 і 4 залишилися у різних групах.
        Check("Елементи 0 і 4 не зв'язані",
            Practical1.ConnectedQuickFind(firstTest, 0, 4), false);

        // Єдиний елемент завжди зв'язаний із самим собою.
        int[] smallestTest = Practical1.CreateInitialArray(1);
        Check("Елемент 0 зв'язаний із собою",
            Practical1.ConnectedQuickFind(smallestTest, 0, 0), true);
    }

    // Порівнює фактичне значення з очікуваним.
    private static void Check(string name, bool actual, bool expected)
    {
        if (actual == expected)
            Console.WriteLine($"УСПІШНО: {name}");
        else
            Console.WriteLine($"ПОМИЛКА: {name}. Очікувалося {expected}, отримано {actual}");
    }
}
```

## 8. Теоретичний аналіз алгоритму

### Quick Find

Основна операція в `Union` — перевірка `id[i]`. Цикл проходить увесь масив, тому для `n` елементів виконується `n` перевірок. Складність `Union` — `O(n)`, а `Connected` — `O(1)`, бо порівнюються два значення. Масив потребує `O(n)` пам’яті.

### Quick Union

Основна операція — перехід від елемента до його батька. Кількість переходів залежить від висоти дерева. У найкращому випадку елемент уже є коренем, у найгіршому може знадобитися до `n` переходів. Найгірша складність пошуку кореня та `Union` — `O(n)`. Масив `parent` потребує `O(n)` пам’яті.
