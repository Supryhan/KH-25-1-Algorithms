## 2. Теоретичні відомості

### 2.1. Стиснення даних

**Стиснення даних** змінює подання інформації так, щоб вона займала менше місця.

- **Стиснення без втрат** дозволяє повністю відновити початкові дані.
- **Стиснення з втратами** допускає втрату частини інформації заради меншого розміру.

У роботі розглядається лише стиснення без втрат.

### 2.2. RLE

**RLE** — *Run-Length Encoding*, або кодування довжин серій. Послідовність однакових символів замінюється символом і кількістю його повторень.

```text
aaa → a3
bb  → b2
cccc → c4
```

Для рядка `aaabbccccd`:

```text
aaabbccccd → a3b2c4d1
```

RLE добре стискає дані з довгими серіями однакових символів, але може збільшувати рядок без повторень:

```text
abcd → a1b1c1d1
```

У навчальній реалізації початковий рядок складається лише з літер. Числа в стисненому рядку позначають кількість повторень.

Стиснення й відновлення потребують `O(n)` часу, де `n` — кількість оброблених символів. Результат потребує `O(n)` пам’яті.

### 2.3. Алгоритмічне зведення

**Зведення** означає перетворення однієї задачі на іншу, для якої вже відомий алгоритм.

Наприклад, задачу «чи є в масиві однакові числа?» можна звести до сортування:

1. створити копію масиву;
2. відсортувати її;
3. порівняти сусідні елементи;
4. якщо сусіди однакові, дублікат існує.

```text
[4, 2, 7, 2]
       ↓ сортування
[2, 2, 4, 7]
 ↑  ↑
Два сусідні числа 2 однакові → результат true
```

Якщо сортування має складність `O(n log n)`, перевірка сусідів — `O(n)`, тому весь розв’язок має складність `O(n log n)`.

У теорії складності зведення також використовують, щоб порівнювати складність задач. Якщо задача `A` швидко зводиться до задачі `B`, то алгоритм для `B` можна використати для `A`. Для доведення складності важливо чітко вказувати напрямок зведення.

### 2.4. Оптимізаційна задача 0/1-рюкзака

Є предмети з вагами й цінностями та рюкзак обмеженої місткості. Кожен предмет можна взяти один раз або не брати.

Формалізація:

- `weight[i]` — вага предмета `i`;
- `value[i]` — його цінність;
- `capacity` — максимальна сумарна вага;
- `x[i]` дорівнює `1`, якщо предмет обрано, і `0` — якщо ні.

Потрібно максимізувати:

```text
value[0]·x[0] + value[1]·x[1] + ...
```

за обмеження:

```text
weight[0]·x[0] + weight[1]·x[1] + ... ≤ capacity
```

### 2.5. Повний перебір і бітова маска

Для `n` предметів існує `2ⁿ` наборів. Число `mask` використовується як набір нулів і одиниць: кожен біт показує, чи обрано відповідний предмет.

Для трьох предметів:

```text
mask = 000 → нічого
mask = 001 → предмет 1
mask = 010 → предмет 2
mask = 011 → предмети 1 і 2
...
mask = 111 → усі предмети
```

Повний перебір має часову складність `O(n · 2ⁿ)`. Для трьох або чотирьох предметів це прийнятно, але зі збільшенням `n` кількість варіантів зростає дуже швидко.

### 2.6. Класи обчислювальної складності

**P** — задачі, для яких відомий алгоритм із поліноміальним часом. Приклади з роботи: RLE і пошук дублікатів через сортування.

**NP** — задачі прийняття рішення, для яких запропонований розв’язок можна перевірити за поліноміальний час. Назва не означає «неполіноміальні».

**NP-повна задача** належить до `NP` і є не менш складною за всі інші задачі цього класу за поліноміальними зведеннями. Версія рюкзака як питання «чи існує набір допустимої ваги з цінністю не меншою за задану?» є NP-повною.

**NP-складна задача** не простіша за NP-повні задачі, але не обов’язково є задачею прийняття рішення або належить до `NP`. Оптимізаційна версія 0/1-рюкзака є NP-складною.

| Клас або вид | Просте пояснення | Приклад у роботі |
|---|---|---|
| `P` | можна розв’язати за поліноміальний час | RLE, дублікати через сортування |
| `NP` | готове рішення можна швидко перевірити | рішення версії рюкзака «так/ні» |
| NP-повна | одна з найскладніших задач у `NP` | задача прийняття рішення про рюкзак |
| NP-складна | щонайменше така складна, як NP-повні | оптимізаційний 0/1-рюкзак |

### 2.7. Обов’язковий наочний приклад RLE

Початковий рядок:

```text
aaabbccccd
```

Покрокова обробка:

```text
Серія aaa   → a3
Серія bb    → b2
Серія cccc  → c4
Серія d     → d1

Стиснений рядок: a3b2c4d1
```

Відновлення:

```text
a3 → aaa
b2 → bb
c4 → cccc
d1 → d

Результат: aaabbccccd
Перевірка початковий == відновлений: true
```

### 2.8. Обов’язковий наочний приклад рюкзака

```text
Ваги:      [2, 3, 4]
Цінності:  [4, 5, 7]
Місткість: 5
```

| Маска | Обрані предмети | Вага | Цінність | Допустимо |
|---|---|---:|---:|---|
| `000` | немає | 0 | 0 | так |
| `001` | 1 | 2 | 4 | так |
| `010` | 2 | 3 | 5 | так |
| `011` | 1, 2 | 5 | 9 | так |
| `100` | 3 | 4 | 7 | так |
| `101` | 1, 3 | 6 | 11 | ні |
| `110` | 2, 3 | 7 | 12 | ні |
| `111` | 1, 2, 3 | 9 | 16 | ні |

Оптимальний допустимий набір — предмети `1` і `2`, його цінність дорівнює `9`.

## 6. Кодовий приклад

Метод `CompressRle` рахує послідовні однакові символи. `DecompressRle` читає символ і наступне за ним число, яке може складатися з кількох цифр. Метод пошуку дублікатів сортує копію, щоб не змінювати початковий масив.

### Файл `Source/Practical12.cs`

```csharp
using System.Text;

namespace TheoryOfAlgorithms.Source;

public static class Practical12
{
    public static string CompressRle(string text)
    {
        if (text.Length == 0) return "";

        StringBuilder result = new StringBuilder();
        int count = 1;

        for (int i = 1; i <= text.Length; i++)
        {
            if (i < text.Length && text[i] == text[i - 1])
                count++;
            else
            {
                result.Append(text[i - 1]);
                result.Append(count);
                count = 1;
            }
        }
        return result.ToString();
    }

    public static string DecompressRle(string compressed)
    {
        StringBuilder result = new StringBuilder();
        int i = 0;

        while (i < compressed.Length)
        {
            char symbol = compressed[i++];
            int count = 0;

            // Читаємо всі цифри кількості, наприклад 12.
            while (i < compressed.Length &&
                   compressed[i] >= '0' && compressed[i] <= '9')
            {
                count = count * 10 + (compressed[i] - '0');
                i++;
            }

            for (int repeat = 0; repeat < count; repeat++)
                result.Append(symbol);
        }
        return result.ToString();
    }

    public static bool HasDuplicatesUsingSorting(int[] values)
    {
        int[] copy = (int[])values.Clone();
        Array.Sort(copy); // Зводимо задачу пошуку дублікатів до сортування.

        for (int i = 1; i < copy.Length; i++)
            if (copy[i] == copy[i - 1]) return true;
        return false;
    }

    public static int SolveKnapsack(int[] weights, int[] values,
                                    int capacity, out int bestMask)
    {
        int bestValue = 0;
        bestMask = 0;
        int variants = 1 << weights.Length; // 2 у степені n.

        for (int mask = 0; mask < variants; mask++)
        {
            int totalWeight = 0;
            int totalValue = 0;

            for (int item = 0; item < weights.Length; item++)
            {
                if ((mask & (1 << item)) != 0)
                {
                    totalWeight += weights[item];
                    totalValue += values[item];
                }
            }

            if (totalWeight <= capacity && totalValue > bestValue)
            {
                bestValue = totalValue;
                bestMask = mask;
            }
        }
        return bestValue;
    }

    public static void PrintSelectedItems(int mask, int itemCount)
    {
        for (int item = 0; item < itemCount; item++)
            if ((mask & (1 << item)) != 0)
                Console.Write($"{item + 1} ");
        Console.WriteLine();
    }

    public static void Run()
    {
        string text = "aaabbccccd"; // Дані індивідуального варіанта.
        string compressed = CompressRle(text);
        string restored = DecompressRle(compressed);

        Console.WriteLine($"Початковий рядок: {text}");
        Console.WriteLine($"RLE: {compressed}");
        Console.WriteLine($"Відновлений рядок: {restored}");
        Console.WriteLine($"Рядки однакові: {text == restored}");

        int[] numbers = { 4, 2, 7, 2 };
        Console.WriteLine($"Є дублікати: " +
                          $"{HasDuplicatesUsingSorting(numbers)}");

        int[] weights = { 2, 3, 4 };
        int[] values = { 4, 5, 7 };
        int bestValue = SolveKnapsack(weights, values, 5, out int bestMask);
        Console.WriteLine($"Найкраща цінність: {bestValue}");
        Console.Write("Обрані предмети: ");
        PrintSelectedItems(bestMask, weights.Length);
    }
}
```

## 7. Перевірка коректності

Тестовий випадок містить конкретні дані й відомий очікуваний результат. Перевірка успішна, якщо стиснення відновлюється без втрат, дублікат визначається правильно, а цінність рюкзака збігається з очікуваною.

| № | Вхідні дані | Що перевіряється | Очікуваний результат |
|---:|---|---|---|
| 1 | `aaabbccccd` | Звичайне RLE | `a3b2c4d1`, відновлення правильне |
| 2 | порожній рядок | Граничний випадок | порожній результат |
| 3 | `abcd` | Відсутність серій | `a1b1c1d1` |
| 4 | `[1,2,3]` і `[1,2,1]` | Дублікати | `false` і `true` |
| 5 | ваги `[2,3,4]`, цінності `[4,5,7]`, місткість `5` | Рюкзак | найкраща цінність `9` |

### Файл `Tests/Practical12Tests.cs`

```csharp
using TheoryOfAlgorithms.Source;

namespace TheoryOfAlgorithms.Tests;

public static class Practical12Tests
{
    public static void RunTests()
    {
        string compressed = Practical12.CompressRle("aaabbccccd");
        CheckText("RLE", compressed, "a3b2c4d1");
        CheckText("Відновлення",
            Practical12.DecompressRle(compressed), "aaabbccccd");

        CheckBool("Дублікат є",
            Practical12.HasDuplicatesUsingSorting(new[] { 1, 2, 1 }), true);
        CheckBool("Дубліката немає",
            Practical12.HasDuplicatesUsingSorting(new[] { 1, 2, 3 }), false);

        int best = Practical12.SolveKnapsack(
            new[] { 2, 3, 4 }, new[] { 4, 5, 7 }, 5, out _);
        CheckNumber("Рюкзак", best, 9);
    }

    private static void CheckText(string name, string actual, string expected)
    {
        Console.WriteLine(actual == expected
            ? $"Успішно: {name}" : $"Помилка: {name}");
    }

    private static void CheckBool(string name, bool actual, bool expected)
    {
        Console.WriteLine(actual == expected
            ? $"Успішно: {name}" : $"Помилка: {name}");
    }

    private static void CheckNumber(string name, int actual, int expected)
    {
        Console.WriteLine(actual == expected
            ? $"Успішно: {name}" : $"Помилка: {name}");
    }
}
```

## 8. Теоретичний аналіз алгоритмів

| Алгоритм або задача | Основна операція | Часова складність | Додаткова пам’ять |
|---|---|---|---|
| RLE-стиснення | порівняння сусідніх символів | `O(n)` | `O(n)` для результату |
| RLE-відновлення | додавання відновлених символів | `O(k)` | `O(k)` для результату |
| Дублікати через сортування | сортування й порівняння сусідів | `O(n log n)` | залежить від сортування |
| Повний перебір рюкзака | перевірка предметів кожної маски | `O(n · 2ⁿ)` | `O(1)` без результату |

`k` — довжина відновленого рядка. Збільшення кількості предметів на один подвоює кількість наборів повного перебору.
