## 2. Теоретичні відомості

### 2.1. Граф

**Граф** складається з вершин і ребер. Вершини можуть позначати міста, комп’ютери, користувачів або інші об’єкти, а ребра — зв’язки між ними.

```text
0 —— 1
|    |
2 —— 3
```

У **неорієнтованому графі** ребро `(0, 1)` дозволяє рухатися і від `0` до `1`, і від `1` до `0`.

В **орієнтованому графі** дуга `0 → 1` дозволяє рухатися лише у вказаному напрямку.

### 2.2. Список суміжності

У списку суміжності для кожної вершини зберігається список її сусідів.

```text
0: 1, 2
1: 0, 3
2: 0, 3
3: 1, 2
```

Для неорієнтованого ребра `(0, 1)` потрібно виконати два додавання: `1` до списку вершини `0` та `0` до списку вершини `1`. Для орієнтованої дуги `0 → 1` виконується лише перше додавання.

### 2.3. Пошук у глибину

**DFS** — *Depth-First Search*, або пошук у глибину, рухається від поточної вершини до ще не відвіданого сусіда настільки далеко, наскільки можливо. Після цього алгоритм повертається назад.

У прикладі DFS реалізовано рекурсивним методом. Масив `visited` зберігає `true` для вже відвіданих вершин, щоб алгоритм не ходив по колу.

### 2.4. Пошук у ширину

**BFS** — *Breadth-First Search*, або пошук у ширину, спочатку відвідує всіх сусідів початкової вершини, потім сусідів цих сусідів.

BFS використовує чергу. У навчальному коді черга представлена звичайним масивом та двома індексами:

- `queueStart` — позиція наступної вершини для вилучення;
- `queueEnd` — позиція для додавання нової вершини.

У неваговому графі BFS знаходить шлях із найменшою кількістю ребер.

### 2.5. Шлях і масив `parent`

Коли BFS уперше переходить із вершини `current` до `next`, програма записує:

```text
parent[next] = current
```

Після завершення пошуку можна рухатися від кінцевої вершини через `parent` до початкової, а потім перевернути отриману послідовність.

### 2.6. Компоненти зв’язності

**Компонента зв’язності** неорієнтованого графа — це група вершин, між якими існують шляхи. Щоб порахувати компоненти, програма запускає DFS із кожної ще не відвіданої вершини. Один запуск DFS відвідує одну компоненту.

Для орієнтованих графів існують слабкі та сильні компоненти зв’язності. У цій початковій роботі підрахунок компонентів виконується лише для неорієнтованого графа.

### 2.7. Часова і просторова складність

Якщо граф подано списками суміжності, DFS і BFS мають часову складність `O(V + E)`, де `V` — кількість вершин, а `E` — кількість ребер. Кожна вершина відвідується не більше одного разу, а кожне ребро переглядається обмежену кількість разів.

Масиви `visited`, `parent` і черга потребують `O(V)` додаткової пам’яті. Списки суміжності зберігають `O(V + E)` значень.

| Позначення | Значення | Приклад |
|---|---|---|
| `V` | кількість вершин | для вершин `0..6`: `V = 7` |
| `E` | кількість ребер | для п’яти пар: `E = 5` |
| `O(V + E)` | перегляд вершин і ребер | `7 + 5 = 12` основних об’єктів |

### 2.8. Обов’язковий наочний приклад

Нехай є неорієнтований граф із ребрами:

```text
(0,1), (0,2), (1,3), (2,3), (4,5)
```

Схема:

```text
0 —— 1       4 —— 5       6
|    |
2 —— 3
```

**DFS від вершини `0`:**

```text
Відвідуємо 0
0 → 1: відвідуємо 1
1 → 3: відвідуємо 3
3 → 2: відвідуємо 2

Порядок DFS: 0, 1, 3, 2
```

**BFS від вершини `0`:**

```text
Черга: [0]
Вилучаємо 0, додаємо 1 і 2: [1, 2]
Вилучаємо 1, додаємо 3: [2, 3]
Вилучаємо 2: [3]
Вилучаємо 3: []

Порядок BFS: 0, 1, 2, 3
```

**Шлях від `0` до `3`:**

```text
parent[1] = 0
parent[3] = 1
Зворотний рух: 3 ← 1 ← 0
Результат: 0 → 1 → 3
```

**Компоненти зв’язності:**

```text
1: {0, 1, 2, 3}
2: {4, 5}
3: {6}

Кількість компонентів: 3
```

## 6. Кодовий приклад

Метод `BuildGraph` отримує масив ребер і параметр `directed`. Значення `false` будує неорієнтований граф, а `true` — орієнтований. DFS виводить вершини одразу, а BFS повертає масив `parent` для відновлення шляху.

### Файл `Source/Practical7.cs`

```csharp
using System.Collections.Generic;

namespace TheoryOfAlgorithms.Source;

public static class Practical7
{
    public static List<int>[] BuildGraph(int vertexCount, int[,] edges,
                                         bool directed)
    {
        List<int>[] graph = new List<int>[vertexCount];
        for (int i = 0; i < vertexCount; i++)
            graph[i] = new List<int>();

        for (int i = 0; i < edges.GetLength(0); i++)
        {
            int from = edges[i, 0];
            int to = edges[i, 1];
            graph[from].Add(to);
            if (!directed) graph[to].Add(from);
        }
        return graph;
    }

    public static void Dfs(List<int>[] graph, int vertex, bool[] visited)
    {
        visited[vertex] = true;
        Console.Write($"{vertex} ");

        foreach (int next in graph[vertex])
            if (!visited[next]) Dfs(graph, next, visited);
    }

    public static int[] Bfs(List<int>[] graph, int start, bool showOrder)
    {
        bool[] visited = new bool[graph.Length];
        int[] parent = new int[graph.Length];
        for (int i = 0; i < parent.Length; i++) parent[i] = -1;

        int[] queue = new int[graph.Length];
        int queueStart = 0;
        int queueEnd = 0;
        queue[queueEnd++] = start;
        visited[start] = true;

        while (queueStart < queueEnd)
        {
            int current = queue[queueStart++];
            if (showOrder) Console.Write($"{current} ");

            foreach (int next in graph[current])
            {
                if (!visited[next])
                {
                    visited[next] = true;
                    parent[next] = current;
                    queue[queueEnd++] = next;
                }
            }
        }
        return parent;
    }

    public static void PrintPath(int[] parent, int start, int target)
    {
        int[] reversePath = new int[parent.Length];
        int length = 0;
        int current = target;

        while (current != -1)
        {
            reversePath[length++] = current;
            if (current == start) break;
            current = parent[current];
        }

        if (current == -1)
        {
            Console.WriteLine("Шляху немає");
            return;
        }

        for (int i = length - 1; i >= 0; i--)
        {
            Console.Write(reversePath[i]);
            if (i > 0) Console.Write(" → ");
        }
        Console.WriteLine();
    }

    public static int CountComponents(List<int>[] graph)
    {
        bool[] visited = new bool[graph.Length];
        int count = 0;

        for (int vertex = 0; vertex < graph.Length; vertex++)
        {
            if (!visited[vertex])
            {
                count++;
                DfsWithoutOutput(graph, vertex, visited);
            }
        }
        return count;
    }

    private static void DfsWithoutOutput(List<int>[] graph, int vertex,
                                         bool[] visited)
    {
        visited[vertex] = true;
        foreach (int next in graph[vertex])
            if (!visited[next]) DfsWithoutOutput(graph, next, visited);
    }

    public static void Run()
    {
        int vertexCount = 7;
        int[,] edges = { { 0, 1 }, { 0, 2 }, { 1, 3 },
                         { 2, 3 }, { 4, 5 } }; // Дані варіанта.
        List<int>[] graph = BuildGraph(vertexCount, edges, false);

        Console.Write("DFS від 0: ");
        Dfs(graph, 0, new bool[vertexCount]);
        Console.WriteLine();

        Console.Write("BFS від 0: ");
        int[] parent = Bfs(graph, 0, true);
        Console.WriteLine();

        Console.Write("Шлях 0 → 3: ");
        PrintPath(parent, 0, 3);
        Console.WriteLine($"Компонент зв'язності: {CountComponents(graph)}");
    }
}
```

## 7. Перевірка коректності

Тестовий випадок містить конкретний граф, початкову вершину та очікуваний результат. Перевірка успішна, якщо знайдено правильний `parent` або правильну кількість компонентів.

| № | Вхідні дані | Що перевіряється | Очікуваний результат |
|---:|---|---|---|
| 1 | граф прикладу | Компоненти | `3` |
| 2 | одна вершина без ребер | Найменший граф | `1` компонента |
| 3 | 4 вершини без ребер | Ізольовані вершини | `4` компоненти |
| 4 | ребра `(0,1), (1,2)` | Шлях | `0 → 1 → 2` |
| 5 | ребро `(0,1)`, пошук від `0` до `2` | Відсутній шлях | шляху немає |

        Check("Три компоненти", Practical7.CountComponents(graph), 3);

        int[,] pathEdges = { { 0, 1 }, { 1, 2 } };
        List<int>[] pathGraph = Practical7.BuildGraph(3, pathEdges, false);

## 8. Теоретичний аналіз алгоритмів

| Алгоритм | Основна операція | Часова складність | Додаткова пам’ять |
|---|---|---|---|
| DFS | перехід до невідвіданого сусіда | `O(V + E)` | `O(V)` |
| BFS | додавання та вилучення вершини з черги | `O(V + E)` | `O(V)` |
| Підрахунок компонентів | серія запусків DFS | `O(V + E)` | `O(V)` |

Зі збільшенням кількості вершин і ребер зростає кількість елементів, які потрібно переглянути. Один повний обхід списків суміжності не повинен повторно обробляти вже відвідані вершини.

**Додаткова зміна:** додайте ребро `(4,5)`.

**Підказка для тестів:** два маршрути до `4`; ізольована `5`; одна компонента після зміни.

### Варіант 9. Взаємодія модулів

**Вхідні дані:** `V=5`; ребра `(0,1), (1,2), (2,4), (0,3)`; початок `0`, ціль `4`.

**Очікуваний результат:** шлях `0→1→2→4`; компонент — `1`.

**Додаткова зміна:** видаліть ребро `(1,2)`.

**Підказка для тестів:** шлях до `3`; усі вершини; відсутній шлях після зміни.

### Варіант 10. Туристичні маршрути

**Вхідні дані:** `V=7`; ребра `(0,1), (1,2), (2,5), (0,3), (3,4)`; початок `0`, ціль `5`.

**Очікуваний результат:** шлях `0→1→2→5`; компонент — `2`.

**Додаткова зміна:** додайте ребро `(4,6)`.

**Підказка для тестів:** ізольована `6` до зміни; шлях до `4`; дві компоненти.

### Варіант 11. Канали зв’язку

**Вхідні дані:** `V=6`; ребра `(0,1), (1,3), (3,5), (0,2), (2,4)`; початок `0`, ціль `5`.

**Очікуваний результат:** шлях `0→1→3→5`; компонент — `1`.

**Додаткова зміна:** додайте ребро `(4,5)`.

**Підказка для тестів:** шлях до `4`; усі вершини; альтернативний маршрут.

### Варіант 12. Залежності задач

**Вхідні дані:** `V=7`; ребра `(0,1), (1,2), (0,3), (3,4), (5,6)`; початок `0`, ціль `4`.

**Очікуваний результат:** шлях `0→3→4`; компонент — `2`.

**Додаткова зміна:** додайте ребро `(4,5)`.

**Підказка для тестів:** шлях до `2`; окрема пара `5–6`; одна компонента після зміни.
