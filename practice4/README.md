## 2. Теоретичні відомості

### 2.1. Стратегія «розділяй і володарюй»

Стратегія складається з трьох простих дій:

1. **Розділити** велику задачу на менші частини.
2. **Розв’язати** кожну меншу частину.
3. **Об’єднати** часткові результати.

Наприклад, масив із шести чисел можна поділити на дві частини по три числа, окремо відсортувати їх, а потім об’єднати.

### 2.2. Рекурсія і базовий випадок

**Рекурсія** виникає, коли метод викликає сам себе з меншою частиною даних. Щоб виклики не тривали нескінченно, потрібен **базовий випадок**.

Для сортування базовим є масив або частина масиву з нульовим чи одним елементом: вона вже впорядкована.

```text
[7] → сортувати більше нічого
```

### 2.3. Merge Sort

Merge Sort послідовно ділить масив навпіл, доки не залишаться частини з одного елемента. Потім алгоритм зливає сусідні впорядковані частини.

Основна операція — порівняння перших ще не використаних елементів двох частин. Часова складність у звичайному, найкращому та найгіршому випадках становить `Θ(n log n)`. Для тимчасового масиву потрібна додаткова пам’ять `O(n)`.

Простий інваріант злиття: перед кожною новою вставкою вже заповнена частина тимчасового масиву впорядкована і містить найменші з оброблених елементів.

### 2.4. Quick Sort

Quick Sort вибирає **опорний елемент** — `pivot`. У цій роботі опорним завжди є останній елемент поточної частини. Після поділу:

- елементи, не більші за `pivot`, розташовані ліворуч;
- `pivot` стоїть на остаточному місці;
- більші елементи розташовані праворуч.

Потім ліва і права частини сортуються рекурсивно.

У середньому Quick Sort має часову складність `Θ(n log n)`. Якщо останній елемент щоразу виявляється найменшим або найбільшим, поділ стає нерівномірним, а складність може погіршитися до `Θ(n²)`. Пам’ять рекурсивних викликів у середньому становить `O(log n)`, у найгіршому випадку — `O(n)`.

Простий інваріант поділу: під час проходу всі елементи до індексу `smaller` не більші за `pivot`, а переглянуті елементи після нього — більші за `pivot`.

### 2.5. Позначення складності

- `O(...)` — верхня оцінка зростання кількості операцій;
- `Ω(...)` — нижня оцінка;
- `Θ(...)` — однакова швидкість зростання зверху і знизу.

| Складність | Приблизна кількість операцій для `n = 10` | Просте пояснення |
|---|---:|---|
| `O(1)` | 1 | Розмір даних майже не впливає на кількість дій |
| `O(log n)` | 3–4 | Дані на кожному рівні суттєво зменшуються |
| `O(n)` | 10 | Потрібно переглянути всі елементи |
| `O(n log n)` | 30–40 | Є кілька рівнів, на кожному переглядаються елементи |
| `O(n²)` | 100 | Для кожного елемента переглядається багато інших |

### 2.6. Обов’язковий наочний приклад Merge Sort

Початковий масив:

```text
[6, 3, 8, 2, 5]
```

**Поділ:**

```text
[6, 3, 8, 2, 5]
       /        \
 [6, 3, 8]     [2, 5]
   /    \       /   \
[6, 3]  [8]   [2]   [5]
 /  \
[6] [3]
```

**Злиття:**

```text
[6] + [3]       → [3, 6]
[3, 6] + [8]    → [3, 6, 8]
[2] + [5]       → [2, 5]
[3, 6, 8] + [2, 5] → [2, 3, 5, 6, 8]
```

Кінцевий результат: `[2, 3, 5, 6, 8]`.

### 2.7. Обов’язковий наочний приклад Quick Sort

Візьмемо той самий масив. Перший `pivot` — останнє число `5`.

```text
Початок: [6, 3, 8, 2, 5]
```

Порівнюємо з `5`:

```text
6 > 5  → залишається праворуч
3 ≤ 5  → переноситься ліворуч: [3, 6, 8, 2, 5]
8 > 5  → залишається праворуч
2 ≤ 5  → переноситься ліворуч: [3, 2, 8, 6, 5]
```

Ставимо `pivot` між двома групами:

```text
[3, 2, 5, 6, 8]
       ↑
```

Число `5` уже стоїть на остаточному місці. Після рекурсивного сортування частин `[3, 2]` і `[6, 8]` отримуємо:

```text
[2, 3, 5, 6, 8]
```

## 6. Кодовий приклад

Приклад сортує масив `[6, 3, 8, 2, 5]`. Параметри `left` і `right` позначають межі частини масиву, з якою зараз працює рекурсивний виклик. Змінна `comparisons` передається з `ref`, щоб усі виклики збільшували один спільний лічильник.

### Файл `Source/Practical4.cs`

```csharp
namespace TheoryOfAlgorithms.Source;

public static class Practical4
{
    public static void MergeSort(int[] values, int left, int right,
                                 ref int comparisons, bool showSteps = true)
    {
        if (left >= right) return; // Частина з одного елемента вже впорядкована.

        int middle = (left + right) / 2;
        MergeSort(values, left, middle, ref comparisons, showSteps);
        MergeSort(values, middle + 1, right, ref comparisons, showSteps);
        Merge(values, left, middle, right, ref comparisons);

        if (showSteps)
            PrintArray($"Merge [{left}..{right}]", values);
    }

    private static void Merge(int[] values, int left, int middle, int right,
                              ref int comparisons)
    {
        int[] temp = new int[right - left + 1]; // Результат одного злиття.
        int i = left;
        int j = middle + 1;
        int k = 0;

        while (i <= middle && j <= right)
        {
            comparisons++;
            if (values[i] <= values[j]) temp[k++] = values[i++];
            else temp[k++] = values[j++];
        }

        while (i <= middle) temp[k++] = values[i++];
        while (j <= right) temp[k++] = values[j++];

        // Повертаємо впорядковані числа з temp у початковий масив.
        for (int index = 0; index < temp.Length; index++)
            values[left + index] = temp[index];
    }

    public static void QuickSort(int[] values, int left, int right,
                                 ref int comparisons, bool showSteps = true)
    {
        if (left >= right) return; // Базовий випадок рекурсії.

        int pivotIndex = Partition(values, left, right, ref comparisons);
        if (showSteps)
            PrintArray($"Pivot {values[pivotIndex]}", values);

        QuickSort(values, left, pivotIndex - 1, ref comparisons, showSteps);
        QuickSort(values, pivotIndex + 1, right, ref comparisons, showSteps);
    }

    private static int Partition(int[] values, int left, int right,
                                 ref int comparisons)
    {
        int pivot = values[right]; // Останній елемент є опорним.
        int smaller = left - 1;

        for (int current = left; current < right; current++)
        {
            comparisons++;
            if (values[current] <= pivot)
            {
                smaller++;
                Swap(values, smaller, current);
            }
        }

        Swap(values, smaller + 1, right);
        return smaller + 1; // Остаточна позиція опорного елемента.
    }

    private static void Swap(int[] values, int first, int second)
    {
        int temp = values[first];
        values[first] = values[second];
        values[second] = temp;
    }

    public static void Run()
    {
        int[] numbers = { 6, 3, 8, 2, 5 }; // Дані індивідуального варіанта.
        int[] mergeValues = (int[])numbers.Clone();
        int[] quickValues = (int[])numbers.Clone();
        int mergeComparisons = 0;
        int quickComparisons = 0;

        PrintArray("Початковий масив", numbers);
        MergeSort(mergeValues, 0, mergeValues.Length - 1,
                  ref mergeComparisons);
        QuickSort(quickValues, 0, quickValues.Length - 1,
                  ref quickComparisons);

        PrintArray("Merge Sort", mergeValues);
        PrintArray("Quick Sort", quickValues);
        Console.WriteLine($"Порівняння Merge Sort: {mergeComparisons}");
        Console.WriteLine($"Порівняння Quick Sort: {quickComparisons}");
    }

    public static void PrintArray(string name, int[] values)
    {
        Console.WriteLine($"{name}: [{string.Join(", ", values)}]");
    }
}
```


Вхідні дані містяться в масиві `numbers` у методі `Run`. Саме цей масив потрібно замінити даними свого варіанта. Методи `MergeSort` і `QuickSort` викликають самі себе для менших частин, а `Merge` і `Partition` виконують основну роботу.

## 7. Перевірка коректності

Тестовий випадок — це конкретний масив і відомий очікуваний результат. Якщо фактичний масив після сортування збігається з очікуваним, перевірка успішна.

| № | Вхідні дані | Що перевіряється | Очікуваний результат |
|---:|---|---|---|
| 1 | `[6, 3, 8, 2, 5]` | Звичайний випадок | `[2, 3, 5, 6, 8]` |
| 2 | `[4]` | Один елемент | `[4]` |
| 3 | `[]` | Порожній масив | `[]` |
| 4 | `[3, 1, 3]` | Однакові значення | `[1, 3, 3]` |
| 5 | `[1, 2, 3, 4]` | Уже впорядкований масив | `[1, 2, 3, 4]` |

### Файл `Tests/Practical4Tests.cs`

```csharp
using TheoryOfAlgorithms.Source;

namespace TheoryOfAlgorithms.Tests;

public static class Practical4Tests
{
    public static void RunTests()
    {
        int[] mergeValues = { 6, 3, 8, 2, 5 };
        int mergeCount = 0;
        Practical4.MergeSort(mergeValues, 0, mergeValues.Length - 1,
                             ref mergeCount, false);
        Check("Merge Sort", mergeValues, new[] { 2, 3, 5, 6, 8 });

        int[] quickValues = { 3, 1, 3 };
        int quickCount = 0;
        Practical4.QuickSort(quickValues, 0, quickValues.Length - 1,
                             ref quickCount, false);
        Check("Quick Sort з повторенням", quickValues, new[] { 1, 3, 3 });

        int[] empty = { };
        int emptyCount = 0;
        Practical4.MergeSort(empty, 0, empty.Length - 1,
                             ref emptyCount, false);
        Check("Порожній масив", empty, new int[] { });
    }

    private static void Check(string name, int[] actual, int[] expected)
    {
        bool equal = actual.Length == expected.Length;
        for (int i = 0; i < actual.Length && equal; i++)
            if (actual[i] != expected[i]) equal = false;

        Console.WriteLine(equal ? $"Успішно: {name}" : $"Помилка: {name}");
    }
}
```

## 8. Теоретичний аналіз алгоритмів

| Алгоритм | Основна операція | Звичайний випадок | Найгірший випадок | Додаткова пам’ять |
|---|---|---|---|---|
| Merge Sort | порівняння під час злиття | `Θ(n log n)` | `Θ(n log n)` | `O(n)` |
| Quick Sort | порівняння з `pivot` | `Θ(n log n)` | `Θ(n²)` | у середньому `O(log n)` |

Для Merge Sort початковий порядок чисел мало впливає на загальну структуру поділів. У наведеному Quick Sort уже впорядкований або зворотно впорядкований масив може створювати дуже нерівномірні частини, тому кількість порівнянь зростає.

**Додаткова зміна:** додайте `40`.

**Підказка для тестів:** упорядковані дані; два елементи; повторення.

### Варіант 11. Номери аудиторій
