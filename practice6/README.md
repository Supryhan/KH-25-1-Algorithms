## 2. Теоретичні відомості

### 2.1. Таблиця символів

**Таблиця символів** зберігає пари **«ключ — значення»**. Ключ використовується для пошуку, а значення — це пов’язані з ним дані.

```text
Ключ     Значення
cat      3
dog      5
fox      2
```

Типові операції:

- `Put(key, value)` — додати нову пару або змінити значення наявного ключа;
- `Get(key)` — знайти значення за ключем;
- перевірити, чи існує ключ.

### 2.2. Таблиця на основі послідовного пошуку

Найпростіший варіант використовує два масиви: в одному зберігаються ключі, у другому — відповідні значення.

```text
Індекс:    0      1      2
Ключі:   [cat,   dog,   fox]
Значення:[  3,     5,     2]
```

Щоб знайти `dog`, програма послідовно порівнює ключ із `cat`, а потім із `dog`. Пошук у найгіршому випадку має складність `O(n)`. Додавання в кінець за наявності вільного місця — `O(1)`, але перевірка, чи ключ уже існує, потребує `O(n)`.

### 2.3. Бінарне дерево пошуку

У **бінарному дереві пошуку** для кожного вузла виконується правило:

- менші ключі розташовані ліворуч;
- більші ключі розташовані праворуч.

Порівняння рядків у C# виконується методом `string.Compare`. Для ключів `cat`, `dog`, `fox`, доданих саме в такому порядку, просте дерево матиме вигляд:

```text
cat
  \
  dog
    \
    fox
```

У середньому пошук і додавання мають складність `O(log n)`, якщо дерево не надто витягнуте. Для невдалого порядку вставки дерево може перетворитися на ланцюжок, і складність погіршиться до `O(n)`.

### 2.4. Збалансоване дерево

**Збалансоване дерево пошуку** автоматично підтримує приблизно однакову висоту лівих і правих частин. Для тих самих трьох ключів бажана форма така:

```text
    dog
   /   \
 cat   fox
```

У збалансованому дереві пошук, додавання та видалення гарантовано виконуються приблизно за `O(log n)`. Прикладами є AVL-дерево та червоно-чорне дерево.

Повна реалізація балансування потребує поворотів вузлів і багатьох додаткових умов. У цій початковій роботі студент порівнює просте і збалансоване дерева на схемах, але не реалізує механізм поворотів самостійно.

### 2.5. Хеш-таблиця

**Хеш-функція** перетворює ключ на індекс масиву. У навчальному прикладі додаються числові коди символів ключа, а сума ділиться з остачею на розмір таблиці.

```text
Hash("cat") = (99 + 97 + 116) % 7 = 4
```

Якщо два ключі отримали однаковий індекс, виникає **колізія**. У прикладі використано лінійне пробування: програма переходить до наступної позиції, доки не знайде вільне місце або потрібний ключ.

За доброго розподілу ключів `Put` і `Get` у середньому мають складність `O(1)`. Якщо колізій дуже багато, складність може погіршитися до `O(n)`.

### 2.6. Часова і просторова складність

| Структура | Пошук у звичайному випадку | Найгірший випадок | Чи зберігає порядок ключів |
|---|---|---|---|
| Послідовна таблиця | `O(n)` | `O(n)` | у порядку додавання |
| Просте дерево пошуку | `O(log n)` | `O(n)` | так |
| Збалансоване дерево | `O(log n)` | `O(log n)` | так |
| Хеш-таблиця | `O(1)` | `O(n)` | ні |

Усі структури потребують `O(n)` пам’яті для зберігання `n` пар.

### 2.7. Обов’язковий наочний приклад

Додамо пари:

```text
cat → 3
dog → 5
fox → 2
```

**Послідовна таблиця:**

```text
Після Put("cat", 3): [cat:3]
Після Put("dog", 5): [cat:3, dog:5]
Після Put("fox", 2): [cat:3, dog:5, fox:2]

Get("dog"):
cat != dog
dog == dog
Результат: 5
```

**Просте дерево пошуку:**

```text
cat — корінь
dog > cat → dog праворуч
fox > cat і fox > dog → fox праворуч від dog

cat
  \
  dog
    \
    fox
```

**Хеш-таблиця розміру 7:**

```text
Hash(cat) = 4 → позиція 4
Hash(dog) = 6 → позиція 6
Hash(fox) = 4 → колізія, наступна вільна позиція 5

Індекс: [0, 1, 2, 3, 4,   5,   6]
Ключі:  [_, _, _, _, cat, fox, dog]
```

Перевірки:

```text
Get("dog") → 5
Get("owl") → ключ відсутній
```

## 6. Кодовий приклад

Для спрощення місткість масивів задається заздалегідь. Значення `null` у масиві ключів означає вільну позицію. Метод `Get` повертає `null`, якщо ключ не знайдено.

### Файл `Source/Practical6.cs`

```csharp
namespace TheoryOfAlgorithms.Source;

public static class Practical6
{
    public class Node
    {
        public string Key;
        public int Value;
        public Node? Left;
        public Node? Right;

        public Node(string key, int value)
        {
            Key = key;
            Value = value;
        }
    }

    public static int? SequentialGet(string[] keys, int[] values,
                                     int count, string searchKey)
    {
        for (int i = 0; i < count; i++)
            if (keys[i] == searchKey) return values[i];
        return null;
    }

    public static Node PutTree(Node? node, string key, int value)
    {
        if (node == null) return new Node(key, value);

        int comparison = string.Compare(key, node.Key,
                                        StringComparison.Ordinal);
        if (comparison < 0) node.Left = PutTree(node.Left, key, value);
        else if (comparison > 0) node.Right = PutTree(node.Right, key, value);
        else node.Value = value;
        return node;
    }

    public static int? TreeGet(Node? node, string searchKey)
    {
        while (node != null)
        {
            int comparison = string.Compare(searchKey, node.Key,
                                            StringComparison.Ordinal);
            if (comparison == 0) return node.Value;
            node = comparison < 0 ? node.Left : node.Right;
        }
        return null;
    }

    public static int Hash(string key, int tableSize)
    {
        int sum = 0;
        foreach (char symbol in key) sum += symbol;
        return sum % tableSize;
    }

    public static void HashPut(string?[] keys, int[] values,
                               string key, int value)
    {
        int index = Hash(key, keys.Length);
        while (keys[index] != null && keys[index] != key)
            index = (index + 1) % keys.Length;
        keys[index] = key;
        values[index] = value;
    }

    public static int? HashGet(string?[] keys, int[] values, string searchKey)
    {
        int index = Hash(searchKey, keys.Length);
        int checkedPositions = 0;
        while (keys[index] != null && checkedPositions < keys.Length)
        {
            if (keys[index] == searchKey) return values[index];
            index = (index + 1) % keys.Length;
            checkedPositions++;
        }
        return null;
    }

    public static void Run()
    {
        string[] keys = { "cat", "dog", "fox" }; // Дані варіанта.
        int[] values = { 3, 5, 2 };

        Console.WriteLine("Послідовна таблиця:");
        for (int i = 0; i < keys.Length; i++)
            Console.WriteLine($"{keys[i]} → {values[i]}");

        Node? root = null;
        foreach (int i in new[] { 0, 1, 2 })
            root = PutTree(root, keys[i], values[i]);

        string?[] hashKeys = new string?[7];
        int[] hashValues = new int[7];
        for (int i = 0; i < keys.Length; i++)
            HashPut(hashKeys, hashValues, keys[i], values[i]);

        Console.WriteLine($"Sequential Get(dog): " +
                          $"{SequentialGet(keys, values, keys.Length, "dog")}");
        Console.WriteLine($"Tree Get(dog): {TreeGet(root, "dog")}");
        Console.WriteLine($"Hash Get(dog): {HashGet(hashKeys, hashValues, "dog")}");
        Console.WriteLine($"Hash Get(owl): " +
                          $"{HashGet(hashKeys, hashValues, "owl")?.ToString() ?? "не знайдено"}");

        Console.WriteLine("Хеш-таблиця:");
        for (int i = 0; i < hashKeys.Length; i++)
            Console.WriteLine($"{i}: {hashKeys[i] ?? "_"}");
    }
}
```

## 7. Перевірка коректності

Тестовий випадок містить конкретні пари, ключ для пошуку й очікуване значення. Якщо фактичний результат збігається з очікуваним, перевірка успішна.

| № | Вхідні дані | Що перевіряється | Очікуваний результат |
|---:|---|---|---|
| 1 | `cat→3, dog→5, fox→2`, ключ `dog` | Наявний ключ | `5` у трьох структурах |
| 2 | `cat→3`, ключ `cat` | Один елемент | `3` |
| 3 | порожня таблиця, ключ `cat` | Порожній набір | `null` |
| 4 | ключ `owl` | Відсутній ключ | `null` |
| 5 | `cat→3`, потім `cat→9` у дереві й хеш-таблиці | Оновлення | `9` |

### Файл `Tests/Practical6Tests.cs`

using TheoryOfAlgorithms.Source;

namespace TheoryOfAlgorithms.Tests;

public static class Practical6Tests
{
    public static void RunTests()
    {
        string[] keys = { "cat", "dog", "fox" };
        int[] values = { 3, 5, 2 };
        Check("Послідовний пошук",
            Practical6.SequentialGet(keys, values, 3, "dog"), 5);

        Practical6.Node? root = null;
        root = Practical6.PutTree(root, "cat", 3);
        root = Practical6.PutTree(root, "dog", 5);
        Check("Пошук у дереві", Practical6.TreeGet(root, "dog"), 5);
        Check("Відсутній ключ", Practical6.TreeGet(root, "owl"), null);

        string?[] hashKeys = new string?[7];
        int[] hashValues = new int[7];
        Practical6.HashPut(hashKeys, hashValues, "cat", 3);
        Practical6.HashPut(hashKeys, hashValues, "cat", 9);
        Check("Оновлення в хеш-таблиці",
            Practical6.HashGet(hashKeys, hashValues, "cat"), 9);
    }

    private static void Check(string name, int? actual, int? expected)
    {
        Console.WriteLine(actual == expected
            ? $"Успішно: {name}" : $"Помилка: {name}");
    }
}

## 8. Теоретичний аналіз алгоритмів

Основною операцією є порівняння ключів або обчислення індексу.

| Структура | Від чого залежить кількість операцій | Пошук | Пам’ять |
|---|---|---|---|
| Послідовна таблиця | від позиції ключа | `O(n)` | `O(n)` |
| Просте дерево | від висоти дерева | у середньому `O(log n)`, найгірше `O(n)` | `O(n)` |
| Збалансоване дерево | від логарифмічної висоти | `O(log n)` | `O(n)` |
| Хеш-таблиця | від кількості колізій | у середньому `O(1)`, найгірше `O(n)` | `O(n)` |

**Потрібно:** знайти `taskA`; перевірити `taskD`.

**Очікуваний результат:** `taskA→3`; `taskD` не знайдено.

**Додаткова зміна:** оновіть `taskB→8`.

**Підказка для тестів:** перший ключ; відсутній ключ; оновлення.

### Варіант 10. Рейтинг фільмів

**Вхідні дані:** `filmA→8`, `filmB→6`, `filmC→9`.

**Потрібно:** знайти `filmC`; перевірити `filmD`.

**Очікуваний результат:** `filmC→9`; `filmD` не знайдено.

**Додаткова зміна:** додайте `filmD→7`.

**Підказка для тестів:** новий ключ; один запис; порожня таблиця.

### Варіант 11. Коди аудиторій

**Вхідні дані:** `roomA→201`, `roomB→305`, `roomC→110`.

**Потрібно:** знайти `roomB`; перевірити `roomD`.

**Очікуваний результат:** `roomB→305`; `roomD` не знайдено.

**Додаткова зміна:** оновіть `roomC→115`.

**Підказка для тестів:** середній ключ; оновлення; відсутній ключ.

### Варіант 12. Пріоритети інцидентів

**Вхідні дані:** `low→1`, `medium→2`, `high→3`.

**Потрібно:** знайти `high`; перевірити `critical`.

**Очікуваний результат:** `high→3`; `critical` не знайдено.

**Додаткова зміна:** додайте `critical→4`.

**Підказка для тестів:** новий ключ; перший ключ; порожня таблиця.

## 14. Тестові завдання

1. Що зберігає таблиця символів?
   - A. Пари «ключ — значення»
   - B. Лише випадкові числа
   - C. Лише графічні файли
   - D. Тільки відсортовані масиви

2. Яка складність послідовного пошуку в найгіршому випадку?
   - A. `O(1)`
   - B. `O(log n)`
   - C. `O(n)`
   - D. `O(n log n)`

3. Де в дереві пошуку розташовують ключ, менший за ключ вузла?
   - A. У корені
   - B. Ліворуч
   - C. Праворуч
   - D. У хеш-таблиці

4. Яка перевага збалансованого дерева?

   - B. Воно завжди має один вузол
   - C. Воно не використовує порівняння
   - D. Його висота залишається приблизно логарифмічною

5. Що робить хеш-функція?
   - A. Перетворює ключ на індекс
   - B. Сортує всі ключі
   - C. Видаляє значення
   - D. Будує дерево

6. Що таке колізія?
   - A. Відсутність ключів
   - B. Повністю заповнене дерево
   - C. Однаковий індекс для різних ключів
   - D. Помилка компіляції

7. Що поверне `Get("dog")` для пар `cat→3`, `dog→5`?
   - A. `3`
   - B. `5`
   - C. `null`
   - D. `dog`

8. Яка середня складність пошуку в добрій хеш-таблиці?
   - A. `O(n²)`
   - B. `O(n)`
   - C. `O(log n)`
   - D. `O(1)`

9. Яку структуру варто вибрати, якщо ключі потрібно отримувати у впорядкованому порядку?
   - A. Дерево пошуку
   - B. Хеш-таблицю без додаткового сортування
   - C. Звичайний стек
   - D. Чергу

10. Що означає результат `null` методу `Get` у прикладі?

    - B. Таблиця відсортована
    - C. Ключ не знайдено
    - D. Ключ знайдено двічі
